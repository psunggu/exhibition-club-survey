## 날짜 설문 — `date-survey.gs`

회원이 톡방 링크를 눌러 휴대폰(카카오톡 인앱 브라우저)에서 답하고, 운영진은 응답 시트의 「취합」 을 보고 날짜를 정한다. 투표 결과는 지금처럼 톡방에서 나눈다.

**분기형(`setupBranchForm`)을 쓴다.** 모두에게 토요일 칸을 묻고, 「평일 낮에 시간이 되시나요?」 에 예라고 한 사람만 평일 낮 칸을 더 고른다. 직장인 회원은 토요일만 고르고 끝난다. 직업은 묻지 않는다 — 받는 것은 이름(필수)과 구역(선택)뿐이다. 같은 파일에 간단형 · 시트형 함수도 있지만 쓰지 않는다(시트형은 이름이 든 시트 링크를 톡방에 올려야 해서 개인정보 원칙과 부딪힌다).

> **시트 링크 · 폼 편집 링크는 톡방 · 저장소 · 다른 어디에도 올리지 않는다.** 응답 시트에는 회원 이름이 들어 있다. 톡방에는 「응답 링크」 하나만 올린다.

### 1. 붙여 넣기와 설정

1. 운영진 구글 계정(개인 gmail 도 된다)으로 https://script.google.com → **새 프로젝트**. 이름은 「○월 정기관람 날짜 설문」.
2. `Code.gs` 의 글을 모두 지우고 `date-survey.gs` 전체를 붙여 넣은 뒤 저장(⌘S).
3. 맨 위 `CONFIG` 만 고친다.
   - `formTitle` · `exhibition` — 전시 이름 · 장소 · 운영 시간 · 관람료. 주최 측에 확인했으면 `factsConfirmed: true`(폼의 「확인 중」 문구가 빠진다).
   - `deadline` · `announceDate` · `keepUntil` · `targetMonth` — 마감 · 발표일 · 응답 보관 기한 · 대상 달.
   - `weekendDates` — 본 모임 후보. **토요일만** 넣는다(일요일은 뺀다 — 2026-10-06 운영자). 토요일이 아니면 실행할 때 멈춘다.
   - `weekdayDates` — 평일 낮 후보(화~금). 월요일은 휴관을 확인하기 전에는 넣지 않는다(`allowMonday`).
   - `slots` — 시간대. 전시장 운영 시간에 맞춘다.
   - `noteDates` — 사진 교체 등으로 쉴 수 있는 날을 따로 알린다.
   - 잘못된 날짜(대상 달 밖 · 마감 전 · 없는 날짜 · 월요일)를 넣으면 아무것도 만들기 전에 멈추고 무엇이 틀렸는지 알려 준다.

### 2. 실행과 권한 승인

1. 함수 목록에서 `setupBranchForm` → **실행**.
2. 「승인 필요」 → **권한 검토** → 계정 선택. 권한 화면에 체크칸이 보이면 **모두 선택**.
3. 「Google에서 확인하지 않은 앱」 경고는 직접 붙여 넣은 스크립트라 뜬다. **고급** → **(프로젝트 이름)(으)로 이동** → **허용**. 직접 붙여 넣은 스크립트가 아니면 여기서 멈춘다.
4. 실행 로그에 응답 링크 · 짧은 링크 · 폼 편집 링크 · 응답 시트 링크 · 게시 상태 · 링크가 들어간 톡방 안내문이 찍힌다.
5. 중간에 멈췄으면 같은 함수를 다시 실행한다. 이미 만든 폼은 새로 만들지 않고 남은 설정(트리거 · 자동 마감 · 안내 시트 · 취합)을 마저 한다.

### 3. 올리기 전에 확인

1. 로그의 「게시 상태: 게시됨」 을 본다. 폼 편집기 오른쪽 위 **게시됨 → 응답자 관리**가 「링크가 있는 모든 사용자」 인지 본다. 막혀 있으면 회원에게 로그인 화면이 뜨고, 카톡 인앱 브라우저에서는 구글 로그인이 막혀 답할 수 없다.
2. 스크립트는 로그인이 필요한 설정을 모두 꺼 둔다 — 이메일 수집 안 함, 응답 1회 제한 끔(켜면 구글 로그인을 요구한다), 파일 업로드 문항 없음, 응답 요약 비공개(켜면 다른 회원의 이름이 보인다).
3. **휴대폰 카톡에서 시험 응답 한 건.** 응답 링크를 「나와의 채팅」 에 보내 카톡 안에서 열고 끝까지 낸다. 「취합」 에 1명으로 잡히는지 본 뒤, 폼 편집기 **응답 → 개별 보기**에서 지우고 `refreshTally` 를 실행해 취합을 비운다.

### 4. 마감까지

- 톡방에는 로그의 안내문과 **응답 링크**만 올린다.
- 「취합」 은 응답이 들어올 때마다 다시 계산된다(직접 고치면 다음 계산 때 지워진다). 같은 이름이 여러 번 오면 가장 늦은 응답 하나만 센다. 구역이 다르면 다른 사람으로 본다. **이름 · 구역이 모두 같은 동명이인은 구분하지 못하니** 「응답자별 정리」 를 한 번 훑어본다.
- 날짜를 빼거나 바꿀 때는 폼 편집기에서 격자 줄 · 선택지를 고치지 않는다. CONFIG 를 고친 뒤 `forceNew: true` 로 다시 실행하고(전 폼은 응답 받기가 꺼진다) `false` 로 되돌린다.
- `autoCloseAtDeadline: true` 면 마감 시각에 저절로 닫힌다. 일찍 닫으려면 `closeForm` 실행.

### 5. 날짜 정하기와 뒤처리

1. 「취합」 → **인원 많은 후보(위 5개)** 에서 토요일 본 모임 날짜 · 시간대를 고른다.
2. **두 번 나눠 간다면** — 토요일 하나 + 평일 낮 하나로 나눌 때 둘 중 하나라도 올 수 있는 인원이다. 「토요일 후보 인원」 · 「평일 낮 후보 인원」 은 그 후보의 전체 인원이라 둘 다 되는 분이 양쪽에 들어 있다.
3. 톡방에 날짜를 알리고, 사이트 달력에는 `/meetup` 으로 올린다.
4. 모임이 끝나면(늦어도 `keepUntil`) 드라이브에서 응답 시트와 폼을 지우고 **휴지통도 비운다**. 스크립트 편집기 왼쪽 **트리거**(시계)에서 남은 트리거를 지운다. 프로젝트는 다음 달에 CONFIG 만 바꿔 다시 쓴다.

### 문제가 생기면

| 보이는 것 | 할 일 |
|---|---|
| 「이미 만들어 둔 버전 A 가 있어요」 | 정상이다. 새로 만들려면 `forceNew: true` 로 실행하고 `false` 로 되돌린다. |
| 「CONFIG 를 고쳐 주세요」 | 적힌 날짜를 고친다. |
| 회원이 로그인 화면을 본다 | 3-1 — 게시됨 · 「링크가 있는 모든 사용자」 를 확인한다. 우회로는 안내문의 「⋮ → 다른 브라우저로 열기」. |
| 취합이 안 바뀐다 | `refreshTally` 를 직접 실행한다. 트리거 목록에 `onFormSubmitTally` 가 없으면 setup 을 다시 실행한다. |
| 「취합」 맨 위 「… 문항을 찾지 못해 취합을 멈췄어요」 | 폼 편집기에서 바꾼 문항 제목을 되돌리고 `refreshTally` 를 실행한다. |
| 구글이 「트리거 실패」 메일을 보낸다 | `refreshTally` 를 직접 실행해 본다. 같은 오류면 그 문구를 개발 담당에게 보낸다(회원 이름은 빼고). |

### 검증

2026-10-06 에 저장소 밖에서 목(FormApp · SpreadsheetApp · ScriptApp 의 실제 메서드만 받는다)으로 세 setup 과 취합을 시험했다 — 구조 · 문구 · 분기 58건, 취합 반박 시나리오 38건(중복 · 수정 · 동명이인 · 공백 · 자모 분리 · 빈 격자 · 문항 제목 변경 등). 실제 계정에서는 익명 요청(카카오톡 사용자 에이전트)으로 응답 링크가 로그인 없이 열리는 것까지 확인했다. 응답을 고쳤을 때 설치형 트리거가 다시 도는지는 공식 문서에 없어 확인하지 못했다 — 안 돌면 다음 제출이나 `refreshTally` 때 반영된다.

## 옛 운영 시트 — `Code.gs` (가동한 적 없음)

1. https://script.google.com 에 접속합니다.
2. 새 프로젝트를 만듭니다.
3. `Code.gs` 내용을 붙여넣습니다.
4. 함수 선택에서 `setupClubSurveySystem`을 고릅니다.
5. 실행 버튼을 누르고 Google 권한을 승인합니다.
6. 실행이 완료되면 새 Google Sheet와 Google Form 2개가 생성됩니다.
7. 생성된 Sheet의 `설정` 시트에서 다음 링크를 확인합니다.
   - 운영 관리 Sheet URL
   - 7월 참석 설문 응답 URL
   - 전시·공연 추천 설문 응답 URL
8. 응답 URL 2개를 `public/config.js`에 입력합니다.
