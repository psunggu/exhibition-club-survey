# 자동화 준비 계획 — 언제, 무엇을, 얼마나 싸게

> 2026-09-13 작성. `docs/OPERATIONS.md` 가 「지금 어떻게 돌리나」 라면, 이 문서는
> **「어느 시점이 되면 무엇을 자동으로 넘기고, 그때 AI 토큰을 어떻게 아끼나」** 다.
> 지금 당장 바꾸는 것은 없다. 조건이 채워졌을 때 켤 수 있게 순서와 준비물을 적어 둔다.

## 한 줄 결론

**판단이 없는 일은 전부 스크립트로, AI 는 「달라진 것이 있을 때만」 「가장 싼 모델로」 「정해진 프롬프트로」.**
그러면 주간 운영의 AI 토큰은 지금(세션 1회 · 20분)에서 **주 0~1회 짧은 헤드리스 호출**로 내려간다.

## 2. 토큰을 아끼는 다섯 규칙

1. **판단이 없으면 AI 를 부르지 않는다.** 변환 · 검증 · PR · 머지 · 배포는 이미 스크립트다. 세션이 그 위에 붙어 있을 뿐이다.
2. **달라진 것이 있을 때만 부른다.** `recheck` 처럼 「지난주와 같은 페이지는 본문을 싣지 않는」 게이트를 모든 AI 호출 앞에 둔다. diff 가 비면 세션을 열지 않는다.
3. **가장 싼 모델로, 정해진 프롬프트로.** 헤드리스(`claude -p`)에 스킬 프롬프트 하나만 넣고 Haiku/Sonnet 으로 돌린다. 대화형 세션은 컨텍스트가 크다 — 사람이 판단할 때만 연다.
4. **결과는 파일과 PR 로만 남긴다.** AI 가 본문을 길게 설명하지 않게 「표 한 줄 / PR 한 개」 로 출력 형식을 못 박는다.
5. **실패는 조용히 넘기지 않는다.** 자동화가 늘수록 「돌았는데 아무것도 안 했다」 가 늘어난다. 매 자동 실행은 `last_run` 류 기록과 바탕화면 알림(성공·실패·할 일 없음)을 남긴다 — kakao-digest #10 방식.

## 3. 단계와 게이트 — 「특정 시점」 을 조건으로 적는다

각 단계는 **앞 단계가 조건을 채웠을 때만** 켠다. 조건은 전부 로그로 셀 수 있는 것이다.

### 단계 1 · 수집 — A (2026-09-24 맥 이관: 내보내기는 사람, 나머지는 launchd)
**정한 것:** 내보내기는 사람이 하고, `~/KakaoDigest/inbox` 에 저장하면 launchd 가 곧바로 병합·요약한다. 저장을 잊으면 화·금 22:00 remind 알림 → 사람이 inbox 에 저장한다. (윈도우 때는 22:00 고정 작업이 방 창을 못 찾으면 종료 11 풍선 → 손으로 다시 실행이었다, 2026-09-16 감시자 안 기각.)
**왜:** 맥 카톡 자동 내보내기(AppleScript)는 메뉴가 자주 바뀌어 깨질 지점만 늘린다(kakao-digest T4). 저장은 1분이고 그 뒤는 저장 즉시 돈다.
**다시 볼 때:** 저장을 잊어 공개본이 8일 넘게 밀리는 주가 한 달에 둘 이상이면 remind 주기를 늘리거나 맥 카톡 자동 내보내기(kakao-digest T4)를 다시 본다.
**토큰:** 0.

### 단계 2 · 정리봇 공개본을 PR 까지 자동으로 — C
**켜는 조건:** 수집이 (손으로 다시 돌린 것을 포함해) 4주 연속 종료 0 + `digest:public` 이 「실명 잔존으로 멈춤」 없이 4회 연속.
**바꾸는 것:** 따로 도는 06:30 배치(`digest-public-task.sh`)가 새 요약이 있으면 `npm run digest:public` → `validate-weekly-digest` → 브랜치·커밋·PR 까지 한다(영화 배치 `update-movies-task.sh` 와 같은 틀). **머지는 사람이 PR 버튼** — 공개 페이지에 나가는 글이다. 세션은 열지 않는다.
**통과 판정:** 4주 연속 PR 이 사람 손질 없이 머지됨.
**토큰:** 0. (`/digest` 스킬은 손으로 돌릴 때만 남긴다.)
**준비물:** `scripts/digest-public-task.sh`(원본 `.ps1`, 영화 배치 사본에서 시작), PR 본문 틀, 실패 시 되돌리기.

### 단계 3 · 모임 한 줄 → 달력을 AI 없이 — D
**켜는 조건:** 최근 5건의 `/meetup` 입력이 전부 「날짜 · 시각 · 장소 · 제목」 네 조각으로 규칙 파싱 가능했음(로그로 확인).
**바꾸는 것:** `npm run meetup -- "10/17 토 15시 덕수궁·정동길 산책, 시청역 1번 출구 집결"` 이 규칙으로 필드를 채워 `meetups.ts` 에 항목을 넣고 PR 을 연다. 파싱이 안 되는 줄만 `/meetup` (AI) 로 넘긴다.
**토큰:** 대부분 0, 예외 건만 적음.
**준비물:** `scripts/add-meetup.mjs`, 파싱 실패 시 종료 코드 2 + 「AI 로 넘기라」 는 안내.

### 단계 4 · 사실 재확인을 「달라진 주」 에만 — G
**켜는 조건:** 없음 — 지금 바로 할 수 있다.
**바꾸는 것:** `npm run recheck` 가 지난주와 **한 줄이라도 다르면** 그때만 헤드리스 호출(`claude -p --model sonnet` 에 `/recheck` 프롬프트)로 표를 만들고, 같으면 「변화 없음」 한 줄만 로그에 남기고 끝낸다. launchd 주 1회(`com.psunggu.exhibition-recheck`, 월 06:00 — 2026-09-14 만듦, 09-24 맥 이관).
**토큰:** 지금의 1/4 안팎 (전시 정보는 대개 주 단위로 안 바뀐다).
**준비물:** `recheck` 에 `--diff-only` 종료 코드(0 변화 없음 / 3 변화 있음), 배치 스크립트, 헤드리스 호출 한 줄.

### 단계 5 · 시한 관리를 시스템에 — I
**켜는 조건:** kakao-digest K10 구현 완료.
**바꾸는 것:** 공지문 맨 위 「이번 주 안에 해야 할 것 — D-3 예매 마감」. 단계 2 가 켜져 있으면 사이트 정리봇 카드에도 같은 줄이 나간다.
**토큰:** 0.

### 하지 않을 것 (이 계획의 밖)
- **B 자동 게시** — 영구 제외. `AGENTS.md` 금지 4번.
- **F 전시·공연 자동 수집** — 후보 제시까지는 가능(kakao-digest K13)하나 고르는 판단은 사람. 단계 5 뒤에 다시 본다.

## 4. 켜는 순서와 예상 효과

```
지금        사람 20분/주 + 세션 1회       AI: C·D·G
단계 1·4    사람 10분/주 (공지·머지)      AI: G 를 달라진 주만 헤드리스
단계 2      사람 5분/주  (공지·머지 버튼)  AI: D 만 가끔
단계 3      사람 5분/주                   AI: 예외 건만
```

토큰 관점에서 가장 큰 절감은 **단계 4** (매주 확실히 들던 것을 조건부로) 와 **단계 2** (세션을 안 여는 것) 다. 둘 다 코드만으로 되고 실환경 UI 조작이 필요 없다. 단계 1 은 토큰과 무관하지만 **A(사람의 저장)가 안 되면 2 가 의미가 없다.**

## 5. 헤드리스 호출의 모양 (단계 4 용, 준비만)

```
claude -p --model claude-sonnet-5 --output-format text \
  "$(cat .claude/skills/recheck/SKILL.md)  --- 아래 diff 만 보고 표 한 줄씩. 설명 금지. ---  $(cat logs/recheck-diff.md)"
```
- 대화형이 아니라 **컨텍스트가 프롬프트 + diff 뿐**이다. 저장소 전체를 읽지 않는다.
- 출력은 표만. 사람이 읽고 `update` 한 줄을 SQL Editor 에 넣는다 — DB 는 AI 가 만지지 않는다(지금과 같다).
- 비용 상한: diff 가 N줄을 넘으면 호출하지 않고 「사람이 보라」 로 끝낸다.

## 6. 전제 — 이것이 무너지면 위 계획도 무너진다

- **맥 하나가 서버다**(2026-09-24 Windows PC 에서 옮겼다). 켜져 있고 로그인돼 있어야 배치가 돈다 — 잠자던 시각은 깨어난 뒤 한 번 돈다. 다른 컴퓨터로 옮기면 launchd 작업(등록 스크립트는 두 저장소의 `scripts/install-launchd.sh`) · `config.local.json` · 로컬 백업 폴더(`~/Library/Application Support/ExhibitionClub`, `~/Library/Application Support/KakaoDigest`)를 같이 옮겨야 한다.
- **사람의 내보내기.** A 는 사람이 `~/KakaoDigest/inbox` 에 대화를 저장한 주에만 돈다(맥에는 자동 내보내기가 없다).
- **개인정보.** 대화 저장소(`store/`)와 공개본 변환의 실명 검사(`digest:public` 의 멈춤)는 그대로 둔다. 자동화가 늘어도 이 검사를 건너뛰는 옵션은 만들지 않는다.
- **자동 게시 금지.** 어느 단계에서도 톡방에 글을 올리는 코드는 없다.
