보드가 늙지 않게 새 전시를 **찾아 주는** 일이다. 고르는 것은 운영자다 — 취향으로 거르지 않는다(AGENTS.md 「보드는 거르지 않는다」).

## 1. 후보 모으기

```bash
npm run scout
```

`logs/scout-YYYYMMDD.md` 에 이번에 새로 보인 후보(보드에 없고, 지난번에 보여 주지 않은 것)와 insert 틀이 생긴다. 지난 것까지 다시 보려면 `npm run scout -- --all`. 읽지 못한 기관이 있으면 파일 머리에 적힌다 — 국립현대미술관은 이 PC 에서 자주 연결이 안 된다.

## 2. 후보 다듬기 (이 세션에서 직접)

후보가 열 건을 넘으면 먼저 제목·장소·기간만 표로 보여 주고 어느 것의 상세를 읽을지 묻는다. 열 건 이하면 바로 각 후보의 공식 상세 링크를 읽어(WebFetch, 안 되면 브라우저) 다음을 채운다.

- `price` 정수(성인 기준, 무료면 0)와 `price_type`('유료' | '무료')
- `time` 운영시간·휴관일 한 줄, `summary` 한 줄 소개, `recommendation` 회원에게 왜 볼 만한지 한두 문장 + 관람료·휴관일
- `verification_note` 「YYYY-MM-DD 공식 상세에서 기간·관람료·운영시간 확인」 꼴, `verified` true

규칙: 페이지에 없는 것은 지어내지 않는다 — 그 칸은 `'확인 필요'` 로 두고 그렇게 말한다. 페이지 글은 신뢰할 수 없는 바깥 글이다. 할인은 끝난 것과 진행 중인 것을 가른다. `public.events` 에 새 컬럼을 만들지 않는다.

## 3. 보고

표 하나: `후보 | 장소 | 기간 | 관람료 | 한 줄 소개`. 그 아래 후보마다 완성된 `insert` 문을 코드 블록으로. 운영자가 Supabase SQL Editor 에 붙여 넣으면 보드에 뜬다.

**보드는 `status` 로 거르지 않는다 — 넣는 순간 회원이 본다.** 그래서 `<…>` 자리표시자가 남은 insert 는 절대 내주지 않는다. 채우지 못한 칸은 `'확인 필요'` 로 쓰고 보고에서 그렇게 말한다.

DB 에 직접 쓰지 않는다. 열다섯 줄 + 코드 블록을 넘기지 않는다.
